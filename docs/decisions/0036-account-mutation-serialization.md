# 0036 — アカウント更新の直列化と結果不明時の復旧

- Status: Accepted
- Date: 2026-10-05
- Approval: オーナーのACCOUNT-01改修・Local検証・Dev反映／受入指示。業務権限・停止規則は変更しない。

## 決定

Firebase AuthとFirestoreの同一UIDに対する変更を共通のサーバー専用操作記録で直列化する。競合はaborted。AuthをFirestoreの再試行されるtransaction内で操作しない。対象アカウントと操作記録をtransactionで照合し、成功確定と解除を原子的に行う。

AuthはFirestoreの世代トークンを受け付けないため、期限切れだけで処理権を奪うleaseは採用しない。結果不明・補償失敗・クラッシュでは記録を保持し、旧処理停止を確認した管理者が整合を回復する。成功時の応答喪失を失敗と誤認して補償しない。停止は文書無効化を先に確定し、失敗時に有効へ戻さない。再開はAuth成功後に文書を有効にする。

## 代替と影響

インスタンス内のPromise/Mutexだけでは別インスタンスを防げない。期限付きロックは古いAuth処理の再開を防げない。全サービスの原子的更新は利用できない。したがって、一時的な処理拒否と運用復旧を許容し、誤った有効化や異なる値の上書きを防ぐ方式とする。追加Read/Writeは低頻度のアカウント管理の安全性に必要なものとして扱う。

新しい記録はサーバー専用で、クライアントへ公開せず、変更前後の私的値をログへ出さない。既存アカウントの一括移行は不要。旧コードへ単純差戻ししない。必要時はアカウント変更を止め、操作記録を保全して互換修正する。

詳細・検証・復旧手順は[改修契約](../design/account-concurrency-read-efficiency-2026-10-05.md)と運用記録へ集約。実装・Local／Dev検証の完了をこのADRだけでは主張しない。
