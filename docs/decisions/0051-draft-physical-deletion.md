# 0051: 履歴を残さない下書き削除

- Status: Accepted
- Date: 2026-10-31
- 根拠: オーナーが下書きの物理削除・履歴不要・外部キー再利用と、同時操作の安全性検証を承認。

## 決定

下書き本体・保存結果receipt・外部キー予約を同一transactionで除去する。個別削除の墓石や履歴を残さず、全体の新規作成受付世代番号だけで遅延した初回保存を拒否する。保存済み物件の競合はrevisionで検知する。権限・確認画面・保存契約は[データ契約](../design/meeting-prototype-2026-10-03.md#2026-10-31-下書きの物理削除)を正本とする。

## 理由と影響

削除後に旧初回保存が届くとrevision=0でも再作成できてしまう。対象別墓石は「削除記録不要」に反するため採用しない。全体世代方式は個人情報や対象IDを残さず復活を防ぐ代わりに、削除時点で開いていた他の新規未保存画面も開き直しが必要になる。既存保存済み物件は影響を受けない。

削除済みデータの復元経路は設けない。障害時の差戻しでは削除UIを停止し、世代チェックを保持する。旧serverへ無条件に戻さない。一般データの削除規則・バックアップ保持規則はHSC-001で後発検討する。

## 検証

会社／本支店範囲、保存・本登録との競合、二重削除、旧初回保存の再送、予約解放・キー再利用、履歴とreceiptの不存在を隔離Emulatorで検証する。Local画面・Dev配備照合結果は運用記録へ記載する。Prod公開・実データ削除の承認には拡張しない。
