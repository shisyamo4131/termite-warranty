## 決定

オーナーが提示案を採用し、保存・再有効化・CSV取込の改修、同時登録試験とLocal受入れまで指示した。既存branchCodeReservationsを同一transactionで本支店と更新し、保存時の会社内全本支店検索を撤去する。CSVは管理記録から本支店IDを得て本文だけを取得する。新しい記録・検索項目・準備印は設けず、既存IDとデータ形状を維持する。Dev反映は別途明示指示まで禁止。

## 理由・代替案

既存コード管理記録は既に同時登録の競合先になっている。これを使えば新たな移行を要求せず全件検索を削減できる。桁数制限なしの本支店コードを文字列索引の完全一致検索へ置換する案は採用しない。長いコードも会社・コード全文・所有本支店IDで確認する。新しい短い検索項目の追加も不要。

## 互換性・導入・差戻し

通常編集の後勝ち、有効本支店だけの会社内一意性、無効化時の解放、再有効化の取得、親無効化時の保持、空欄／必須条件、先頭ゼロを維持する。CSVは確定時にも取得・照合し既存の変更検知・全件棄却を維持する。管理記録の欠落を実行時に補完しない。導入前・復旧時に本体と記録を照合し、整合時は移行不要。不整合時だけ原因と限定修正を別途扱う。

管理記録を作らないアプリ外の直接書込みで生じた重複の毎回検出は撤去する。正規の保存経路で整合を維持する既存の責任境界は変えない。形式不変のため取得方式だけを旧方式へ戻せるが、別の採用済み変更は巻き戻さない。
