# 0037 共有参照Storeと使用量の観測

- Date: 2026-10-08
- Status: Accepted
- Authority: 同日のオーナー指示「条件付きで②を採用」「採用しよう。…作業開始」。

## Decision

HSの保証グループ・工務店・本支店は有効／無効を含む全件を一つの共有Storeで購読する。Autocompleteは有効な候補に標準filterを適用する。ポータルは認可済み範囲だけを取得する。

操作別のアプリ観測件数をFunctionsの構造化ログへ記録する。Functions内はサーバー計測、直接アクセスはクライアントで集計して認証済みの専用Functionsへ送る。課金件数との一致を求めない。件数・所要時間を仕組みの見直しの契機とし、HSへの請求額や実利用を合わせて判断する。

## Rationale and alternatives

全件購読は無効化・有効化で取得元を切り替えずに済む。一方で未参照の無効文書も読む。計測後に効果が見込める場合は有効全件購読＋無効の必要時キャッシュへ変更する。現時点で二方式の自動切替や課金見積の正確性は要求しない。

計測だけのための全アクセスFunctions経由化は採用しない。計測文書をFirestoreへ追加せず、通知ごとの送信を避ける。業務の変更履歴・監査証跡を新設する決定ではなく、[0011](0011-no-initial-audit-log.md)の監査ログ対象外は維持する。

## Compatibility, rollback and validation

業務文書の移行は不要。新画面だけが名称付与省略を要求し、旧クライアントとポータルの互換性を保つ。差戻しは旧画面・対応Functionsへ揃え、計測ログは業務状態に使わない。新Callableの実配備・既存Cloudログ保持設定変更は別承認。詳細・観測の限界・試験は[設計](../design/reference-store-metrics.md)を参照。
