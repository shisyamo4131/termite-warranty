# 0035: 保証区間に紐づく請求・保険報告と逆順取消

- Status: Accepted
- Date: 2026-10-04
- Decision maker: プロジェクトオーナー
- Evidence: 本Codex会話でレビュー1〜3採用、請求状態管理追加、依存する保険報告と請求の取消を延長取消に先行させる回答、および全状態を戻せば引渡日訂正可とする確認。続く改修・Dev反映指示。

## Decision

初回保証と各10年延長を識別し、請求はその取引単位、保険報告は保証区間に属する5年区間単位で記録する。取消対象の後続状態を先に戻し、過去の処理経験だけの永続ロックを設けない。元イベントと取消イベントを残す。保証番号は不変。

延長取消は直近から。対象区間の請求済み、延長部分にかかる保険報告、現在満了日の案内済みを先に取り消す。保険報告取消は最新の有効な報告を直前状態へ戻す。初回分を含む有効な報告・請求・延長がすべてなくなれば、確認を経て引渡日を訂正できる。

全体取消は例外として影響の一覧と確認を経て許可し、取消前状態を保管して業務抽出から外す。外部での訂正・整合確認はHSが行う。CSV出力は完了操作ではない。

## Rationale and alternatives

物件単位の請求フラグでは初回と複数延長を区別できない。日付だけを識別子にすると、誤延長の取消・再延長や引渡日訂正で対象を誤る。保証取引の安定したIDと期間を併記する。全操作を時系列だけで巻き戻す方式は、無関係な初回請求などを巻き込むため採らない。

## Compatibility and rollback

旧データにない請求状態は要確認。既知の直近保険報告だけは互換読取し、それ以前を推定生成しない。旧記録不足の取消は開発側への個別確認に止める。一括移行・初期化は行わない。新規記録から連続取消を可能にする。

新状態を理解しない旧版への単純差戻しは不可。必要時は報告・請求・取消操作を停止し、データを保持したまま互換修正版をFunctionsとHostingへ揃えて配備する。保険更新経験の旧フィールドは、新規の完全な履歴に対する永続ロックには使わない。

## Validation and remaining decisions

UI・ロジック・データ契約・配備の全7ゲート。区間対応、依存取消の拒否、複数回の逆順取消、請求状態訂正、再延長、引渡日訂正、旧データ・権限・競合・再送を検証する。請求年月・請求先単位、初期過去物件の保険区間選択は既存未決事項を維持する。
