# 0042: プロジェクト所有のガバナンスと検証分類

- Status: Accepted
- Date: 2026-10-10
- Decision owner: Project owner
- Evidence: GOVERNANCE-MANAGER (`01a1015f-0477-7ad3-8b3c-ef77242b4dcf`)で「scaffoldは新規作成時の土台、一度作成したガバナンスはプロジェクト側で自由に改変してよい」と明示。先に採用済みの検証運用改善の第三段階を同じ主リポジトリで実施する。

## Decision

共通由来の契約・参照・検査／生成ツールも白蟻が所有する。以後の保守ではスキルの呼出し・同期・版合わせを要求しない。既存3.0.0の配布元版とhashは来歴だけとしてlockへ保持し、白蟻のローカル契約版は1.0.0から区別する。生成AGENTSは正本から更新し、直接手編集で一致検査を回避しない。

承認済みの参照先明確化だけで能力・承認／安全境界・実行設定・検証動作が変わらないものは、既存の`project-guidance-metadata`を使う。過去のアプリ試験証拠を要求しない。対象変更に権限・保存・実装・検証動作等の影響があれば関連クラスを加える。不明なら全体検証。正本は[検証方針](../../governance/verification-policy.json)、手順は[運用](../operations.md#verification-matrix)。

## Safety and compatibility

所有権変更は実行権限・外部操作・製品仕様・保存契約の変更ではない。オーナー承認、秘密情報保護、差分保全、全体検証へのフォールバックを維持。分類はファイル拡張子だけで自動判定しない。移行・ローカル契約や検査ツール・実効権限・配備の変更では全7ゲートを維持する。

## Validation and rollback

生成と読取検査、再生成の無変更性、古い生成物／不正な方針／サイズ超過の拒否、失敗時の生成物保全を専用検査で確認する。独立ケース判定と、承認済み参照指示の整理で狭い検証選定を確認する。導入の選定ゲート・結果・独立exit・再利用理由はタスク報告にまとめ、成功前に完了としない。

差戻しは今回所有の契約・ツール・JSON・生成物・対応文書だけを変更前へ戻す。他担当の既存差分は戻さない。部分的に旧checkerと新rendererを混在させず、関連差分を一組で戻す。スキル・他プロジェクト・製品データの操作は不要。
