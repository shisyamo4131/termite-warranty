## 確定した日付要件と共通ルール

上棟日は年月日まで必須とする。日不明の上棟日を月初日で推測する案は撤回済み。補完資料で月初日へ変更された4件が実日付確認の結果かは要確認。

確定計算は上棟日に暦日92日を加算し、その日を算出引渡日＝保証開始日＝保険開始日とする。翌日を1日目とし、休日・営業日は考慮しない。受領データの92日運用に合わせるというオーナー指定で90日案を撤回した。暦の3か月後へ換算し直さない。計算の採用と、受領全件の照合済み・外部承諾証拠の受領・実装済みを区別する。

申込年月しか分からないUHは、一括取込時にその月の1日を運用上の申込日とする確定仕様。実申込日の確認とは区別し、元の年月と便宜設定の事実を保持する具体的な形状は今後設計する。上棟日必須とは別。保証番号の年度・新規請求の対象月は申込日基準を維持し、受領日や算出起算日へ置き換えない。本登録後の申込日訂正制約も維持する。HSC/SHSの日付を月初日へ変換しない。

算出起算日を共通処理に渡す以外、過去物件の初回保険報告、5年区間、更新対象月、起算日訂正の制約はHSC/SHSと同じルールを使う。前月が更新報告対象になること、後日の起算日訂正に必要な取消・外部訂正はUH特有の不具合ではない。終了した過去区間を遡及報告する案は追加しない。

## 保証書と、実際の引渡日との差

[受領資料の記録](../requirements/source-materials.md#2026-10-01-追加資料5点の確認)にあるUH保証書は、以前のPDF確認で引渡日の年月日欄がなく、期間の記載は「お施主様引渡日より10年間」だった。算出年月日を保証書へ差し込むことを当然視しない。

算出日と実引渡日が違えば、システム上の保証・保険期間と保証書の文言による期間がずれる可能性がある。フォームではHSが今回の保険申込で誤差を許容と回答し、オーナーが今回92日算出日での管理を採用した。保証発行主体・保険会社の承諾証拠を受領した記録とは区別する。元の上棟日、算出方法、算出起算日を区別して保持・表示する案とし、算出日を確認済みの実引渡日と説明しない。

## 不足項目・出力

| 項目 | 提案と残る確認 |
| --- | --- |
| 物件住所 | 不明を不明のまま扱う案だが、空欄許可はオーナーが保留し現行必須条件を維持。契約Noを住所の保存値へ入れない。保険CSVでの代替記載は保険会社の了承範囲に従う |
| 加盟店名 | 工務店＝ユニバーサルホーム、加盟店＝支店の方針を採用。支店のコード整合性は回答待ち。保険CSVの列・表記は要確認。工務店名や「本店」で加盟店名を代用しない |
| 建面積 | 過去はHS提供資料の値に従う確定方針を維持。実建面積と保険報告用の200㎡案を混同しない。新規分の取得元・200㎡超の確認者は未決 |
| 使用資材 | UHは資材名不要との受領回答があるが、空欄許可はオーナーが保留。現行必須条件を維持し、許可決定後にUH取込と通常編集の検証を揃える。他グループの必須条件を緩めない |
| 保証書・請求 | 「保険付保だけ」から不要と推測しない。システムで必要な範囲と外部作成に必要な項目を確認する。請求の集約単位は保証グループという既回答を使う |

## 満了案内の修正と10年追加の境界

最長保証年数に達した物件は保証延長のための満了案内から除外する。現在20年／最長20年、30年／30年を除外し、10年／20年、20年／30年は他の条件を満たせば対象。将来UHの10年／10年も同じ判定で除外できる。別のUH専用除外フラグを必須としない。保証が残り次の5年区間が必要な保険更新準備は維持する。

この判定だけLocal修正・回帰検証済みとの記録は[運用記録](../operations.md#2026-10-07-保証満了案内の上限判定修正)を参照する。今回その検証を再実行・Dev配備したものではない。UH一括取込みの確定により、条件付きで保留していた最長年数10の選択肢・保存許可を実装準備へ含める。UH向け実装全体は未実施。住所／資材名空欄は別途明示保留で、10年準備を根拠に許可しない。

## 残る確認の整理順序

以下は質問項目を作る順序であり、完成した送付文面・フォームではない。未決事項の管理は[HSC-015](../requirements/house-solution-confirmations/HSC-015-migration-scope-cleaning.md)等の既存台帳へ戻す。古い15問は[当初案](uh-integration-initial-proposal-2026-10-06.md)としてのみ保管する。

1. UHで必要な業務範囲と、取りまとめ元・実際の加盟店の役割を確認する。保証書・請求の要否を先に確かめ、後続を分岐する。請求の集約単位は再質問しない。
2. 受領Excelの形式・対象範囲・取消の入力を具体化する。契約Noは全UHで一意となる確定仕様、過去資料修正は依頼中として区別。取込は新規専用、訂正は通常編集とし再質問しない。
3. 起算日は上棟日＋92日で採用済みとし、90日案・申込月初日への再質問はしない。必要な外部承諾の記録と、算出日を使う出力を整理する。上棟日は年月日必須を維持する。
4. 住所、面積、加盟店情報の不足と出力表記を具体化する。前段の外部了承を列・見本に落とす。
5. 訂正と状態取消、原本保管・過去値照会の必要性を確認する。必要なときだけ保存範囲を追加する。

契約番号の過去資料修正は依頼中。先頭コードとの意図的不一致は許容、住所録エリアコードは対象外。住所／資材名空欄は明示保留、SHS67行目の訂正値は別の確認として残す。物件名＝施主名は[名称統一を導入前改修](../requirements/case-warranties.md#2026-10-07-施主名と物件名を一つの名称へ統一)へ記録済み。これら合意済み要件を再質問せず、取込実装完了とはしない。
