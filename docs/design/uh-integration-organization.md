# UHの所属・請求先・施工加盟店の持ち方

- 状態：2026-10-07、UH一括取込みと工務店＝ユニバーサルホーム・各加盟店＝支店を採用。任意支店コードは工務店内非空一意・変更可能。取込は受領加盟店コード欄で照合し、契約No先頭の意図的不一致は許容。実装・マスタ登録・Dev変更なし。
- 入口：[UH併載の検討資料](uh-integration-proposal-2026-10-06.md)。要件の正本は[支店要件](../requirements/branches-and-addresses.md#2026-10-07-uhの工務店支店と加盟店コード)、採用根拠は[オーナー記録](../requirements/source-materials.md#2026-10-07-uh回答に対するオーナーの仕様確定と再確認連絡)。

## 採用した所属方針

既存の保証グループ → 工務店 → 支店を使い、UHグループ配下の工務店をユニバーサルホーム、各加盟店を支店として扱う。従来の登録・採番の入口である工務店参照を維持する。これはシステム上の管理構造で、加盟法人の法的な親子関係を確認した記録ではない。

支店に任意の支店コードを保持し、固定内部IDと区別する。非空コードは工務店内一意、空欄は複数可、他工務店の同値は可、登録後変更可を採用。変更しても既存物件の支店IDを維持し、次の取込は新コードを使う。HSC/SHSにも任意項目を用意するが必須にはしない。名前だけや契約No先頭から推測せず、受領加盟店コード欄で支店照合する。不一致はUHの要望による場合があり、棄却・自動訂正の理由にしない。

旧住所録のエリアコードは別体系で現時点で対象外。旧仮照合を支店対応の根拠にしない。支店マスタへコードを登録し、選択した工務店配下にコードがなければ全件棄却する。取込後は通常画面で訂正し、支店候補に名前とコードを併記する。[確定要件](../requirements/branches-and-addresses.md#2026-10-07-任意の支店コードと変更方針を確定)、[保存・競合の設計](uh-integration-import.md#支店コードの保存と編集)。書式上限・予約の物理形状・移行は未実装。

以前の「登録用の固定工務店と受領加盟店名だけを保持し、各加盟店は支店登録しない」案は現在の推奨から外す。工務店を置かずグループへ直接所属させる案も撤回済み。既存文書や当初案の履歴より今回の採用要件を優先する。

## 請求・出力・ポータル

請求を保証グループごとにまとめる受領回答と、将来グループへ請求先名・住所等を持たせる検討は維持する。工務店／加盟店名を請求先と自動的に同一視しない。請求先項目・出力形式の具体的設計と実装は未実施。

UHの保険報告では、工務店名と加盟店名のどちらをどの列へ出すか、住所不明をどう表記するかが残る。支店名・受領名を使う条件を明示し、支店未設定を「本店」として代用しない。元の法人・店舗名が異なる場合も、開発側で黙って変更・分解しない。

[UH工務店ポータル除外](../requirements/external-submission-options.md#2026-10-07-uhの工務店ポータル除外を確定)は確定事項。UHに工務店／支店を登録してもポータルの提供対象へ加えない。HS管理者・担当者の利用は既存権限に従う。アカウント発行・既存アカウント・閲覧・更新の全経路で除外を守る具体的な設計と検証は未実施。

## 現行実装との差分と後続の検証

2026-10-07の先行読取では、物件保存は工務店・支店所属、本登録は工務店の所属グループと有効状態を検査し、画面・CSVはマスタの名称を利用する実装だった。新しい所属方針はこの構造を維持するが、支店の加盟店コード項目・一意性検査・取込照合・UHポータル除外は実装済みとはしない。

工務店の必須住所等は、正式情報を確認して扱う。架空住所を作らない。新規登録では工務店・支店・グループの実在と所属を検査し、登録済みの保証グループ・番号・内部IDはマスタ名やコードの訂正だけで振り直さない。コード変更・無効化・名称変更・旧物件の表示／報告との互換性は設計後に検証する。

後続では、正式コードと店舗の対応、コード重複・未知コードの拒否／要確認、先頭ゼロ、所属の不一致・無効状態、採番と再取込、取消・報告状態の保護、表示・CSV、UHポータル除外、HSC/SHSへの非波及、復旧時の参照整合を架空データで検証する。対象・手順・保全・差戻しが決まるまで実マスタ登録・実データ取込は行わない。
