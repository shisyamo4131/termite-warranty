## 1. 結論と確認済みの前提

推奨は、HSC/SHSの標準運用を維持し、UHも同じ物件・保証一覧と保険報告に載せつつ、UHの受付・入力条件・外部向け表記を分ける方式。UHを別システムにしたり、実態不明の加盟店を工務店／支店へ強制的に当てはめたりしない。

ただし「保険付保だけに利用する」が、保証自体を管理しないという意味なのか、10年の保証情報は持つが保証書発行・延長案内を行わないという意味なのかは未確定。推奨案は後者を仮定する。保証そのものの発行者・起算日が異なる回答であれば、後続の保証書・請求・日付に関する質問をその回答に合わせる。

| 区分 | 現時点で扱える内容 |
| --- | --- |
| 確定済み | 初期はHSが全入力。工務店ポータルは残し、利用開始は延期。HSC/SHSの本登録は住所・引渡日・建面積等を必須とする。保証番号の年度は申込日基準。過去の建面積はHS提供資料に従う。 |
| 共通の既決ルール | 過去物件の初回保険適用は、その時点を含む引渡日起算の5年区間から。終了した前半5年を遡って報告しない。CSV出力と報告済み操作は別。取消・外部訂正の対応も分ける。 |
| 受領回答・報告 | UHは10年のみ・保証更新なし・資材名不要。本部から一覧Excelが届くとの説明。加盟店・住所録に不整合がある。申込日は月までしか分からない。「お施主様契約No」の管理が必要という指摘。 |
| 未了承・未確定 | 住所代替の契約No、加盟店名での報告、上棟日＋3か月という起算日、通常200㎡という報告用面積は保険会社との交渉中。UH向けの仕様採用・実装はまだ行っていない。 |

全グループ共通の過去保険の扱いをUH独自の質問として再提示しない。また、既に回答のある「UHは10年」「UHは資材名不要」を単独で聞き直さず、その意味が未確定の業務範囲と例外条件を質問する。

## 2. 仕様・運用の推奨案

| 項目 | HSC/SHS | UHへの提案・必要な運用 |
| --- | --- | --- |
| 基本の管理 | 現行の物件に付く恒久的な保証を継続 | 同じ一覧にUHと明示して載せ、保険期間・取消・報告の共通処理を使う。実際の保証の管理が不要なら、その範囲をQ1で先に確認する。 |
| 受付 | HS入力を維持。将来の会社・支店別ポータルは別途判断 | 当面は本部からの一覧ExcelをHSが受領・確認する方式。件数と頻度を確認し、一覧取込を推奨。自動登録や自動保険報告は行わない。UHのポータル開放を初期範囲へ追加しない。 |

| 申込年月 | 実申込日を使用 | 月しか分からないUHに限り月初日を設定する案。元の年月と「日を便宜設定した」事実を保持する。受領日・入力日で置き換えない。本登録後に申込日を変えられない現行制約も説明する。 |
| 建面積 | 新規は取得・入力、過去はHS提供値 | UH過去データに面積がない場合は、HSが了承した値・補完ルールを提供してから登録する。新規UHまで実建面積を一律200㎡と扱わない。実面積と保険報告用面積を分ける必要があるかQ10で決める。 |

入力条件は画面と保存処理の双方で保証グループに応じて判断する。住所・使用資材・最長年数・起算方法等をグループ設定として整理する案だが、自由な設定画面の新設までを前提にしない。新グループには標準条件を適用し、UH例外は明示した範囲だけとする。後でグループ設定を変えた際、登録済みの起算日・期間を自動的に書き換えない。

### Excelを継続して受ける場合の手順案

1. 原本をHS側で保管し、新規・再送・訂正・取消の別と受領日を明らかにする。入力資料とシステム上の処理状態を分け、受領Excelを報告済み状態の正本にしない。
2. 登録前に、新規候補・既登録候補・訂正候補・確認が必要な行を一覧にする。件数、保証番号、施主契約No、加盟店情報、元の日付と算出日をHSが確認する。
3. 同じExcelの再送を再登録しない。契約Noの一意性が分からない段階では、番号だけで自動上書きしない。部分失敗から再実行しても、成功済み行の再採番・再登録をしない設計が必要。
4. 受領資料から行が消えても自動取消・削除しない。取消・訂正を明示した資料として確認する。報告済み・請求済み・期間等をExcelの空欄で上書きしない。
5. 起算日を変える訂正は共通の逆順取消・期間再計算・外部訂正を使う。報告済みをシステム内で取り消すだけでは、保険会社の記録は変わらない。
6. 保険会社が受理する項目・表記・起算日が未了承の物件は、推定値で本登録・提出せず取込前の確認対象に残す。これは専用の保留業務画面を追加する提案ではない。

継続Excelは外部からの入力資料として残るため、既決の「管理Excelへの二重入力をやめる」と矛盾させない。システムで更新した報告・請求状態を、外部の一覧へ毎回転記する前提は置かない。

## 3. 上棟日＋3か月を共通起算日とする場合の不都合

日付が同じこと自体は、共通の期間計算を使う上では問題ではない。問題は、その日付を実際の引渡日と混同すること、計算ルールが曖昧なこと、保険会社や保証の発行主体が別の起算日を求めること。以下は現行コードの読取に基づく条件付き影響で、Devで発生を確認した障害という意味ではない。

| 問題・影響 | 現行実装／不都合 | 提案する対処 |
| --- | --- | --- |
| 元情報を残せない | 現行保存項目に上棟日・算出方法・施主契約Noがない。引渡日だけに算出値を入れると、後から実日付か判別できない。 | 元の上棟日、日まで確定か、算出方法、運用上の起算日を保持。実引渡日と表示を分ける。 |
| 3か月が曖昧 | 90日加算・暦月3か月・月末繰越で結果が変わる。現行にUH用の3か月加算処理はない。 | 暦月で3か月後の同日、同日がない月は末日へ合わせる案をHS・保険会社と確認。例：2026-11-30→2027-02-28。未採用。 |
| 上棟日も月しか不明 | 便宜的に1日とすると、開始・満了・更新対象月へ影響する。補完資料で4件が月初日へ変わったことだけでは、正式な運用ルールの承認とは言えない。 | 上棟日の日まで確認するか、月初日等の補完ルールを別途了承し、便宜設定と分かるように残す。申込月の1日補完と混同しない。 |
| 月次報告が前後する | 現行の新規抽出・CSVは引渡日、更新抽出は5年後の前日の満了年月を使う。起算日が月初日なら満了は前月末になる。 | UHは了承された起算日で抽出し、保証・保険区間と更新対象月を登録前に表示。出力の「引渡日」へ算出日を入れてよいかも確認。 |
| 後日訂正が重い | 上棟日・算出ルールの訂正で保証と保険の期間が変わる。現行は有効な報告・請求・延長があると引渡日変更を止める。 | 元上棟日を変えただけで連動して確定期間を変更しない。差分確認、必要な状態取消、再計算、HSの外部訂正を経る。 |
| 保証と保険が同日起算でない場合 | 現行は引渡日を両方の起算日としているため、例えば保険だけ受理日開始となる回答では、そのまま対応できない。 | 先にQ2/Q8で日付の意味を確認。異なる回答なら起算日の分離、期間・抽出・CSVの追加設計が必要。 |
| 過去の適用実績との誤認 | 10年前の起算日を設定しても、過去の10年間すべてに保険が適用された意味にはならない。 | 元起算日による5年区切りと、実際に今回初回報告する区間を分ける。共通の既決ルールを維持。 |
| 採番・請求まで誤って動かす | 保証番号の年度と新規請求月は申込日基準。算出した起算日と申込日の年・月が違うことがある。 | 保証番号や新規請求月を上棟日／算出日へ置き換えない。外部の番号を保持するかはQ7で先に確認。 |
| 開始前の案件 | 算出日が未来でも、受領・登録時点で既に保険適用中とは言えない。 | 登録と対象月による報告を分け、起算日前の月の新規対象へ入れない。開始前と分かる表示・確認を設計する。 |

架空例：上棟日2026-04-01、起算日2026-07-01なら、現行の周年前日計算で保証は2026-07-01〜2036-06-30。保険は2026-07-01〜2031-06-30、2031-07-01〜2036-06-30。後半へ進める更新報告の対象は2031年6月分で、7月分ではない。10年目終了後の3回目の期間は不要。この期間例は現行の計算関数で読取診断済みで、UHの本登録が現在可能という意味ではない。

現行の本登録は上限20／30年のみ、住所・使用資材の必須検証、実在する工務店・所属支店の検証があるため、UHをこの案のまま登録できない。さらに満了アラートは上限を見ていないので、10年追加だけでは保証延長案内の除外は実現しない。期間関数を共用できる部分と改修が必要な部分を分ける。

## 4. HSへの質問案（送付前・オーナーレビュー用）

質問順は「業務範囲・外部了承→受付と識別→日付と不足情報→出力と訂正」。各回答を前提に後続を分岐させ、後から保証書や請求の要否を聞いて前提を覆さない。保険会社との交渉中の項目は「了承済み／交渉中／採用できない」と分ける。交渉中でも事実確認は続けられるが、仕様確定・提出を行わない。

回答済みの共通運用はフォーム冒頭の説明に置き、再質問しない。初期のHS入力、UHの10年・延長なし、UHの資材名不要、全グループ共通の過去保険区間、CSVと報告済み操作の分離を記載する。ただしUHの保証を誰が扱うかはQ1で明確にする。

### Q1　UHで本システムに管理させる業務の範囲

「UHは保険付保のみに利用する」とのご説明について、10年の保証そのものはどなたが発行・管理していますか。本システムで必要なのは、物件情報と保険報告・5年目の継続管理でしょうか。それに加えて、保証書作成用CSV、保証の新規加入に関する請求対象管理も必要ですか。保証書と請求は、それぞれ必要／不要／未定でお答えください。

- 目的：保証期間を管理する意味、発行主体、対象業務を先に決める。
- 分岐：保証書不要ならQ12を省略、請求不要ならQ13を省略。「保険だけ」から無料や請求不要と推定しない。

### Q2　保険会社との交渉結果と適用範囲

ご検討中の①住所の代わりに施主契約Noを記載、②工務店名の代わりに加盟店名を記載、③上棟日から3か月後を保証・保険の起算日として使用、④報告用面積を通常200㎡・200㎡超は実面積とする、について、それぞれ「了承済み／交渉中／採用できない」を教えてください。了承済みの場合は正確な条件と、過去物件・運用開始後の新規物件のどちらへ適用できるかが分かる資料をご提示ください。①は「住所」欄への代替記載か、別の契約No欄か、③は引渡日欄への記載も含めて了承されているかを教えてください。

- 目的：外部で受理されない前提で登録・出力を作り込まない。了承範囲に合わせてQ8/Q10/Q11を具体化する。
- 分岐：過去と新規の条件が違う場合は以降の回答を分ける。未了承の項目は仮案のままとする。

### Q3　継続して届くExcelの提供元と内容

運用開始後も、本部からHS様へUHの一覧Excelが届く理解でよいでしょうか。提供元、受領担当の役割、頻度、毎回の対象（新規分だけ／対象期間の全件／全物件）を教えてください。過去データの初期取込用とは別に、今後使用するExcelの書式をご提示ください。訂正・取消がどのように示されるかも教えてください。

- 目的：一度限りの初期取込と継続受付を分ける。UH側の直接ログインを前提にしない。

### Q4　加盟店の正式情報と維持できる範囲

Excelに記載される加盟店名・コードの正式情報と、加盟・名称変更・退会を管理するのはどなたですか。HS様には変更の連絡が届き、工務店／支店との対応表を維持できますか。維持できない場合、受領Excelの加盟店名・コードをそのまま物件へ保持し、不一致だけ確認する方法で支障はありますか。未掲載・コード相違のある店舗の確認先と、コードの重複・再利用・変更の有無も教えてください。

- 目的：不整合を支店登録で無理に吸収せず、正しい情報の責任者と登録可否を決める。

### Q5　お施主様契約Noの意味と使い方

お施主様契約Noは何を識別する番号で、どなたが発行しますか。UH内の照合・保険報告・訂正連絡など、必要な用途を教えてください。全物件で必須ですか。1つの番号に複数物件が付くこと、別加盟店や別年度で同じ番号になること、番号変更・所有者変更で番号が変わることはありますか。先頭ゼロ等の表記ルールと、番号が分からない場合の照合方法も教えてください。

- 目的：番号を物件と1対1と推定しない。Q14の再送・訂正の照合方式を決める。

### Q6　物件名と施主名の使い分け

申請一覧の「物件名」は「施主名」と同じ意味でしょうか。それとも別々の情報ですか。HSC・SHS・UHで異なる場合は、それぞれの使い分けを教えてください。UHで片方しか届かない場合、受領するのはどちらですか。保険報告の「物件名」にはどの情報を出すべきでしょうか。

- 目的：[HSC-039](../requirements/house-solution-confirmations/HSC-039-property-homeowner-name.md)の未回答事項。名称の自動転記や、施主名必須の解除を推定しない。回答管理はHSC-039へ戻す。

### Q7　UHの保証番号の発行と提供

過去物件の保証番号を維持する方針は変えません。今後の新規UHは、本システムが申込年月を基準に保証番号を発行する運用ですか。それとも本部等が既に発行した番号をExcelで提供しますか。外部発行の場合は、発行者、提供時期、番号重複の防止方法、本システムと本部の間で番号をどう照合するかを教えてください。

- 目的：継続Excelの番号を新規採番で置き換えない。既決の年度・恒久番号を変更する質問ではない。

### Q8　上棟日・引渡日・保証／保険開始日の関係

Q1/Q2の回答を前提に、UHでは「上棟日から3か月後」を、実際の引渡日ではなく、保証・保険の共通の起算日として扱う理解でよいでしょうか。実際の引渡日が分かる物件でも一律にこの計算を使いますか、それとも実引渡日を優先しますか。保証の発行主体・保険会社が定める開始日が違う場合は、それぞれの日付と優先する根拠を教えてください。

- 目的：共通起算日を確定してから計算方式を質問する。保険の実際の過去適用実績まで同一と扱わない。

### Q9　3か月の計算方法と上棟日の日が不明な場合

Q8で3か月後を使う場合、暦の3か月後の同日とし、その日がない月は月末に合わせる方法でよいでしょうか。例：11月30日→翌年2月28日（うるう年なら2月29日）。上棟日も年月までしか分からない物件は、日を確認してから登録しますか、それとも正式な運用ルールで月初日等を設定しますか。今回の補完資料で月初日となった4件は、実日付の確認結果か、便宜的な設定かを教えてください。

- 目的：90日加算や翌月への繰越を勝手に採用しない。日付補完の影響を了承してもらう。

### Q10　申込月と不足する物件情報の扱い

UHの申込年月しか分からない場合は、その月の1日をシステム上の申込日とし、月のみが判明していることを残す方法でよいでしょうか。これは上棟日の補完とは別で、保証番号の年度・新規請求の対象月は申込年月を使います。本登録後の申込日は通常変更できません。後から実申込日や正しい年月が判明することはありますか。

住所が不明なUHは不明のまま登録し、後で分かれば追記する案です。今後のExcelにも住所は含まれませんか。Q2で了承された契約Noがない場合の確認先・対応を教えてください。建面積について、過去分はHS様の提供値を使う方針を維持しますが、今回面積欄のないUHの補完値をご指定ください。新規UHでは実面積を提供できますか。報告用200㎡の条件と実面積の取得有無が違う場合、200㎡超を誰が確認するかも教えてください。

- 目的：空欄を開発側が推測して埋めない。過去の実面積の再収集は求めず、新規UHの情報源を確認する。

### Q11　UHを含む保険報告の列と提出単位

Q2の了承済み条件に従い、UHの報告では、物件名、住所またはその代替、加盟店名、起算日、報告用面積をどの列・表記で出しますか。特に受領済みの見本の「住所」「工務店名」「引渡日」欄へ代替情報を載せるのか、UH用に列や見出しを分けるのかを教えてください。HSC/SHSと同じ月の一覧にまとめて提出してよいですか、それともUHは別の提出単位ですか。現行見本へ記入した例を頂ければ列を照合できます。

- 目的：住所や実引渡日の保存値を代替情報で汚さず、出力時の変換だけを決める。CSV出力後にHSが必要なExcel整形をする既決運用は維持する。

### Q12　保証書の出力項目（Q1で必要／未定の場合のみ）

UHの保証書は誰が作成し、本システムにはどのCSV項目が必要ですか。住所が分からない場合の表記、施主契約Noの使用、Q8の起算日を保証開始日とすることは、保証の発行主体として認められますか。UH用のWordひな型または差し込み項目一覧で確認させてください。

- 目的：保険会社の了承を保証書の了承へ広げない。印刷・送付はシステム外という既決範囲を維持する。

### Q13　UHの請求対象（Q1で必要／未定の場合のみ）

UHの新規加入も請求用一覧へ載せる場合、申込年月で抽出し、UHグループとしてまとめる方法で支障はありますか。本部・加盟店のどちらが請求対象で、現在のExcelに必要な識別情報はありますか。過去分すべて請求済みとのご回答を初期状態へ引き継ぎ、今後の新規分の状態とは分けます。

- 目的：既回答の保証グループ単位・過去請求済みを前提としたUH固有の不足確認。金額・保険料・入金管理は追加しない。

### Q14　再送・訂正・取消の確認方法

Q3/Q5/Q7で確認した番号とExcelの形式を前提に、同じ物件の再送、追加、訂正、取消をどう見分けますか。行がなくなっただけでは取消と扱わず、訂正対象の番号と変更項目、取消対象を明示していただく運用でよいでしょうか。報告済みの起算日等を訂正する場合は、HS様が保険会社へ連絡し、システム側の報告状態・期間を合わせる共通手順を使います。UH本部との訂正連絡の担当・確認方法も教えてください。

- 目的：識別方法を決めた後で差分反映ルールを決める。受領Excelが既存の報告・請求状態を自動上書きする運用にしない。

### Q15　SHSの67行目の日付（UHとは別の補完確認）

SHS申請一覧の67行目について、申込日と保証開始日の正しい年月日をご確認ください。申込日が保証開始日より後の物件を一律に誤りとするものではありません。この行の日付と保証番号の年度の対応を照合し、どの値を訂正するかをご指定ください。

- 目的：入力ミスの可能性が高いというオーナー判断はあるが、訂正値は未確認。番号の一括変更や年の推測訂正はしない。
