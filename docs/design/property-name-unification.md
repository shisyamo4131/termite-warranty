# 物件名・施主名の統合

## 2026-10-08 確定範囲と現在地

オーナーが「物件名と施主は統合。項目名は『物件名』。Dev反映・マイグレーションも含めて作業開始」と指示。一括取込みのDev検証手順と架空テストデータも作成する。HS過去資料の実取込みは回答まで保留。実装・Local検証中、今回のDev反映／移行／HS受入はまだ未実施。

現在の物件／保証propertyWarrantiesはnameとownerNameを別管理している。2026-10-08のDev読取では16件すべてに両項目があり、全件で空でない両名称が一致、不一致0件。履歴の旧ownerName記録は8件ある。実名は記録・ログへ転載しない。

## 新しい契約と互換性

現在名称はnameだけを保存・入力・表示し、ラベルは物件名。CSVも既存「物件名」列だけから保存する。一覧、確認、検索文言、見本保証書で二重表示をなくす。電話番号ownerTelephone、保証番号、外部キー、内部ID、所属、日付、請求／保険、保証期間は維持する。

既存履歴は改変せず、旧ownerNameは「旧履歴の施主名（参考）」として表示する。旧履歴にnameがない場合、現在物件名から過去値を推測しない。新しい手続きのbeforeはnameと電話を記録する。

旧ownerNameを含む保存／本登録要求は再読込を案内して拒否する。新画面は既存文書を編集へ読み込む際に旧項目を除き、全新規・更新で現在のownerNameを保存しない。既存文書の旧名称に不一致／不正値があれば、通常保存・案内等でも変更せず拒否する。既読snapshotを使うためReadは増やさない。物件／保証の現行経路が対象。旧cases/homeowners用の別モデル、工務店ポータルの未統合モデルや個人情報全体の廃止は本変更へ広げない。

## Dev移行・失敗回復・差戻し

通常稼働のまま、別の開発側保守操作と競合しない運用ロックを取得し、現在のnormal世代・(default)・制御DBを照合する。nameの値は維持してownerNameを削除し、revisionだけを+1。updatedAt、履歴、番号、権限、採番等は変更しない。対象は最大300件。名称不一致、欠落した物件名、不正なrevisionは全件拒否する。

移行前name／ownerName／revision、文書全体の型付き変更前・変更後hashを非公開の制御DBnameMigrationsへ保全する。全対象を同一Firestore transactionで原子的に更新し、操作ID／計画hash／世代／件数を(default)の_recovery/nameMigrationへ記録する。適用直前に全対象の変更前hashを比較する。別の通常保存が入っていれば、部分適用せず再計画する。住所移行やバックアップ復元の既存計画を流用しない。

応答不明時はstatusで同じID・hash・owner・checkpointを調べ、旧worker終了を確認して同じIDをresumeする。checkpointが一致すれば、移行後の正当な通常更新を巻き戻さず完了記録を閉じる。checkpointがなければ、変更前hashが一致する場合だけ再実行する。途中結果を推測してロックを削除しない。保全記録破損等で引継ぎ後の確認に失敗した場合も、中断ロックを保持して手動確認する。

差戻しは同じ世代・全対象の変更後hashが一致する場合だけ旧ownerNameを保全値から戻し、revisionをさらに+1。通常更新があれば拒否して個別回復計画を作る。配備は現在名称と外部キー予約を理解する互換版へ戻し、データ・権限・番号の古い全体像を上書きしない。保全像は無断削除しない。

通常FunctionsのReadは追加しない。移行時だけ限定取得、保全／checkpoint、対象16件（実行直前に再確認）のWriteが発生する。バックアップ／PITR停止、Auth、IAM、既存Rules／索引は維持する。健康なDevを停止する方法は今回の設計で選ばないため、通常再開の了承を流用・迂回しない。
