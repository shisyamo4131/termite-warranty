自社情報の編集は共通様式のダイアログへ変更する。基本情報／所在地・連絡先／代表者／振込先で整理し、保存と閉じる操作を設ける。未保存変更の破棄確認、保存中の閉じる防止、最終更新表示、入力の説明領域を維持する。主画面は3案を提示した後、上記の明示指示で「分類カード」を採用した。

## 3. HS会社設定

### 画面と入力

「その他業務 ＞ 設定」を独立したページとして追加し、ページ見出しを「設定」、本文見出しを「自社情報」とする。組織管理・アラート設定は従来の場所を維持する。画面識別子は`companySettings`とし、既存組織管理の`settings`と区別する。

| 区分 | 項目 | 入力条件 |
| --- | --- | --- |
| 基本情報 | 会社名 | 保存時に必須 |
| 基本情報 | 適格請求書発行事業者番号 | 任意。番号の形式確認と、公的な登録の有効性確認を混同しない |
| 所在地・連絡先 | 郵便番号、住所1、住所2、電話番号、FAX番号、メールアドレス | 任意。入力された値の形式を確認 |
| 代表者 | 代表者肩書、代表者名 | 任意 |
| 振込先 | 金融機関名、支店名、預金種別、口座番号、口座名義 | 任意・部分入力可。口座番号は半角数字で先頭ゼロを保持 |

- 住所1は都道府県～町域・番地、住所2は建物名・階・部屋番号等。既存の工務店・本支店の住所項目構成は変更しない。
- 郵便番号からの住所候補は既存の参照方式に寄せ、入力済み住所を無断で上書きしない。電話/FAXの入力規則は既存の半角数字・ハイフンに合わせる。メールは連絡先であり、ログイン・送信元・メール送信設定を変更しない。
- 「編集」でダイアログを開き、「保存」「閉じる」、最終更新日時・更新者を表示。未保存の変更があれば閉じる際に破棄を確認する。未設定の入力は空欄とし、資料やソースにあるHS情報を自動採用しない。削除・有効無効の切替は用意しない。
- 適格請求書発行事業者番号以外も、形式検査だけで実在・到達可能性まで確認済みとは表示しない。
- 既存の見出し、入力説明、メニューとページ共通アイコン、[共通UI規則](clear-sky-theme.md)を使う。

### 保存・権限・読み取り

- HS自身の会社情報を1件だけ、`prototypeSettings/companyProfile` に保存する。型・取得保存操作は[現行データ契約](meeting-prototype-2026-10-03.md#2026-10-12-自社情報請求先の追加保存契約)を参照。工務店マスタへHSを架空の取引先として登録しない。
- システム設定として開発者・HS管理者が編集し、一般HS担当者は参照だけとする。工務店アカウントへ設定画面・設定取得を公開しない。既存の保証グループ編集権限は狭めない。
- 通常操作の保存処理で権限を確認する。現在の直接DB書込みに関するガバナンスを変更する指示ではなく、画面/API制約を全経路の完全な強制と誤認させない。
- 初回参照時に1件を取得し、保存後は共有した設定値を更新する。全物件を読み直さない。ログアウト・利用範囲・復旧世代変更で保持値を破棄する。
- 同時編集は既存マスタに合わせ最後の保存を採用し、編集開始時に最新情報を取得する。新たな承認履歴や競合拒否機能は追加しない。最終更新者・日時は保存側で設定する。
- 復旧作業中は利用停止、確認段階は許可された担当者に読取りのみ。新しい読取り操作を復旧時の許可一覧へ含める。
- Wordに直接書かれた会社名・住所等は自動更新しない。自社情報変更後には既存Wordも確認する旨を画面説明に入れる。

### 不足項目の扱い

指定10項目に、追加指示の振込先5項目を加えて自社情報を管理する。複数口座、ロゴ・社印、請求書番号、支払条件、税・単価は今回先回りして機能追加しない。

## 4. 保証グループの請求先情報

- 1保証グループに現在の請求先1件を持たせる。既存グループ編集内の「請求先」見出しへ8項目を配置する。グループ名と請求先名は別に保持する。
- 保証グループ文書内の請求先専用のまとまりで保存する。請求先名、部署名、担当者名、郵便番号、住所1、住所2、電話番号、メールアドレス。自社設定と同じ住所・連絡先の入力規則を使う。
- 導入時は既存グループに値がなくても読取り可能とし、全項目空欄・部分入力を許容する。既存の登録、保証操作、CSV出力を未設定のために停止しない。将来、請求書を発行する時に必要項目を確認する。
- 工務店・本支店・保証グループ名から自動補完せず、担当者が確認した情報を入力する。同じ会社が複数グループの請求先でも、自動合算・自動同期しない。工務店・支店ごとの別請求先は今回設けない。
- 請求先名等の変更は番号、所属、物件、請求済み状態を変更しない。請求先の編集は既存の保証グループ編集と同じHS利用範囲とする。
- 現行の工務店向け`catalog`は所属グループ文書を丸ごと返すため、追加と同時に必要項目だけを返す形へ変更し、請求先情報を工務店へ返さない。画面で隠すだけで済ませない。
- 旧画面や既存のグループ更新が新項目を消さないよう、未指定と明示的な空欄を区別する。過去データの取込み、マスタ初期値、更新時のフィールド選別も点検する。

### 請求CSVと将来の請求書

今回は請求CSVの11列を維持する。共通化と年月日分割は保証書CSVに適用する。請求CSVへ請求先情報を追加する場合は、既存Excelの利用方法と列追加を別途採用する。請求一覧では選択グループの請求先名または「未設定」を表示して確認できるようにする。

請求書本体を作る将来段階では、発行時点の自社情報・請求先・明細・金額・日付等を請求書ごとに保存し、後日の住所変更で発行済み書類の内容が変わらないようにする。現行の期間別`billingItems`やCSV出力を、請求書発行記録の代わりにしない。税・期限・請求書番号・再発行・訂正はその段階の設計対象。

## 5. 保証書CSVの共通21列

既存6列の名称と位置を維持し、全グループで同じ21列を常時出力する。登録がない任意値も列を省略せず空欄。保証グループの選択、対象年月、期間ごとの行、CSV出力では発行済みにならないことは維持する。

| 順番 | 列名 | 値 |
| ---: | --- | --- |
| 1 | 保証書No | 登録済み保証番号。再採番しない |
| 2 | 物件名 | 現行の統合済み名称。敬称を勝手に追加しない |
| 3 | 引渡日 | YYYY-MM-DD |
| 4 | 担当工務店 | 現行の工務店名 |
| 5 | 担当本支店 | 現行の本支店名。UHの施工加盟店名の利用元 |
| 6 | 住所 | 現行どおり物件住所と建物名を連結 |
| 7 | 保証グループ | グループ名 |
| 8 | 外部キー | 登録値そのまま。UHではお施主様契約Noに差し込む。列名はグループ設定に応じて変えない |
| 9 | 発行対象 | 初回保証、延長保証（1回目）、延長保証（2回目） |
| 10 | 保証開始日 | 最初の保証開始日。延長区間の開始日へ置換しない |
| 11 | 保証満了日 | 選択した発行対象の満了日 |
| 12 | 保証年数 | 最初の開始日から選択した発行対象までの10/20/30。最長保証年数や保険5年と混同しない |
| 13 | 引渡日_年 | 西暦4桁 |
| 14 | 引渡日_月 | 1～12、先頭ゼロなし |
| 15 | 引渡日_日 | 1～31、先頭ゼロなし |
| 16 | 保証開始日_年 | 西暦4桁 |
| 17 | 保証開始日_月 | 1～12、先頭ゼロなし |
| 18 | 保証開始日_日 | 1～31、先頭ゼロなし |
| 19 | 保証満了日_年 | 西暦4桁 |
| 20 | 保証満了日_月 | 1～12、先頭ゼロなし |
| 21 | 保証満了日_日 | 1～31、先頭ゼロなし |

- 日付は登録済みの正しい日付文字列から分割し、時差変換や出力日で補わない。存在しない日付は空欄を捏造せず対象を示して出力を止める。任意値の未登録とは区別する。
- 例：2026-10-08 → 年2026、月10、日8。年・月・日という単位や和暦・敬称はWord側で配置する。
- 既存のBOM付きUTF-8、CRLF、引用符・カンマ・改行の処理、番号の文字列としての扱いを維持。Excel/Wordによる先頭ゼロ等の自動変換は、実際の差込み手順で別途検証する。
- 発行日、CSV出力日、申込日、保険日付は追加しない。CSV出力を発行と扱わず、日付分割はこのCSVに含む3種類に対して行う。
- 自社情報・請求先・保証書記載会社名は保証書CSVへ入れない。担当工務店・担当本支店は現行列として残す。CSVはWordの固定文字を更新しない。

### 期間の具体例と承認境界

| 発行対象 | 保証開始日 | 保証満了日 | 保証年数 |
| --- | --- | --- | ---: |
| 初回保証 | 2026-10-08 | 2036-10-07 | 10 |
| 延長保証（1回目） | 2026-10-08 | 2046-10-07 | 20 |
| 延長保証（2回目） | 2026-10-08 | 2056-10-07 | 30 |

延長後も元の開始日を使う。どの行も物件の最新満了日に置き換えず、選択した初回／延長に対応する満了日・年数を使う。延長済み物件の初回分を再出力する場合にも初回10年の内容とする。元見本の「10年間」固定文字は延長保証の内容に合わせてWord側で変更する必要があり、CSV列追加だけでWord修正済みとは扱わない。

## 6. 導入・再取込み・差戻し

- 実装開始指示を受け、画面、保存処理、保存型、工務店向け返却、復旧試験、再取込み、CSVを影響単位で実装する。保存先は上記現行データ契約へ確定し、実データの一括変換は行わない。
- 新しい設定が存在しない旧データを読めること、業務マスタの追加値が旧形式の更新で消えないことを確かめる。実値は推測で初期投入しない。
- 通常バックアップからの復旧は他の業務データと同じ復旧時点へ戻し、追加値を含め全件照合する。「復旧対象に含める」と「自動バックアップが現在稼働している」は別に確認する。
- 現行の初期取込みはアカウント以外を初期化し、アラート等だけを再作成する。今後の再取込みではHS自社情報・請求先を事前保全し、同一保証グループと確認できた先へ戻して不変を照合する。名前の一致だけで結び付けず、対応不明・重複は停止する。取込計画の内容・照合値にも保全分を含める。
- 上記の再取込み保全は、以前の「アカウント以外は初期化」に対する採用済みの限定的な運用変更。今回の仕様確定は実再取込み・削除・復元の承認ではない。物件と採番は確定原資料に従い、検証番号を残さない既決方針を維持する。設定保全に未対応の旧手順を、追加設定のある環境へそのまま適用しない。
- 差戻しは承認された画面・CSV処理の版へ戻す。追加した設定値を削除せず、旧処理が設定を消さないかを確認する。新形式CSVで作ったWord対応は旧CSVへ戻すとそのまま使えない可能性があるため、採用時に列版・利用手順を併記する。
