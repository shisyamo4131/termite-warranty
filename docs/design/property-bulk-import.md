## 入力形式・検証準備

テンプレートはBOM付きUTF-8のヘッダーのみで、列順は外部キー／支店コード／物件名／申込日／引渡日／上棟日／最長保証期間／現在保証年数／建築面積／住所／郵便番号／建物名／断熱材あり／資材名／施主電話番号／既存保証番号／備考。CSV取込はUTF-8 1MB・300行、保存する物件＋受領＋成功結果の概算6MiBを上限とし、分割を案内する。実Cloud上限の完了証拠ではなく、配備後に合成容量受入を行う。公式上限は[Firestore quotas](https://docs.cloud.google.com/firestore/quotas)と[transactions](https://firebase.google.com/docs/firestore/manage-data/transactions)で確認したリクエスト10MiB／transaction270秒等を別に満たす必要がある。SDKのLocal279件確定は成功したが実サービス試験は未実施。

外部キーはtrimした入力文字列を全物件で一意に使う。提供元・会社・グループ名を自動付加しない。予約IDはsha256(key)、会社内支店コード予約はsha256(companyId＋NUL＋branchCode)。同一実行IDはuid／入力digest／previewHashを照合して成功結果を返し、別内容は拒否する。previewは保存せず、commitは参照・キー・番号・年度カウンターをtransactionで再取得し、読み終えてから全件を書き込む。支店コードは200文字まで、空欄可、制御文字不可。

物件N＋外部キー予約N＋受領N＋成功結果1＋変更年度カウンターのWrite。プレビュー／確定は各対象行のキー予約1＋外部キーlimit(1)＋番号limit(1)、相異なるコードの支店limit(2)、会社・グループ・必要年度・アカウントだけ取得する。0件クエリ・transaction再試行も費用対象になり得るため、実Read数とは区別する。常時全物件／全支店走査はしない。受領／予約／実行記録は復旧対象に追加し双方向照合する。Rulesは既存サーバー所有境界を使い、スタッフ業務の任意直接書込を保証対象にしない。

共通の現在保証年数は10/20/30。受領延長区間はimportedWarrantyPeriodsで識別し、架空の延長履歴は作らず請求をunknownとする。UHは10年固定。終了済み・取消済み行を勝手に有効登録しない。通常編集で外部キーと受領IDは変更不可。通信断に備え、本人／環境単位で操作IDと入力hash等の非本文情報だけをセッションに保全し、statusで本人の結果を確認する。記録なしは未保存を意味せず、同じファイル・ID・previewHashで再確認する。

CSVはUTF-8、先頭ゼロを識別文字列として保持。引用符・カンマ・改行、重複見出し／不足列／過剰行／巨大入力を検査する。数式を実行せず、式や日付の型を黙って推測しない。外部キーの提供元区分、実行IDの同一内容再送、年度別番号保全と受付上限はサーバー契約で固定する。

UHの申込月初日・上棟日＋92日・最長10年は専用の行変換条件であり、共通HSC／SHSへ適用しない。既保証番号・現在保証年数・請求／保険の初期状態は既決の過去物件方針へ合わせる。入力不足・業務終了／取消を行別スキップしない。
