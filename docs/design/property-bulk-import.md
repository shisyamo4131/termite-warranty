### BRANCH-04 詳細化と採用済みTTL

後続のオーナー指示で無効マスタの編集経路をバグとして閉じる。したがって、別担当者が無効のまま改名できることを恒久仕様とはしない。選択済みの5分TTLは維持し、キャッシュの鮮度管理として扱う。再有効化→編集は有効購読へ戻った段階で更新される。

オーナーは追加回答で「5分経過後、次に参照するとき再取得」を選択した。取得成功から5分のTTLとし、表示中に5分ごとの自動取得は行わない。自分のマスタ保存時は対象IDを失効、再有効化で購読値に戻り、logout時はすべて破棄する。無効マスタの通常編集はDISABLED-01で禁止する。5分TTLは購読対象外データの再確認として維持する。以下の構成を推奨設計として整理し、Store実装はまだ開始しない。

- 共通composableを全画面の取得窓口にし、useState等の共有状態に有効文書を保持する。listener解除関数・取得中Promise・ID別の世代管理は内部へ隠す。Nuxt標準useFetchはHTTP取得結果の共有であり、購読解除やremoved処理自体の代わりにはならない。独自の共通取得composableに既存のPromise共有・期限管理を移す構成でよい。
- 参照順は購読の最新値→期限内の個別キャッシュ→同じIDの取得中Promise→個別取得してキャッシュ。キーを環境／DB／復旧世代／ユーザー権限範囲／文書種別／IDで分ける。失敗を不存在扱いで保存しない。キャッシュ件数上限と短時間の不存在キャッシュは実装時に定める内部方針。
- added／modifiedで購読値を更新し、同じIDの個別キャッシュと遅い応答を失効する。removedは有効候補と個別キャッシュから削除し、旧snapshot値を無効文書の最新値として移し替えない。表示に必要なIDだけ再取得する。取得中に再有効化されても、その遅い応答で購読値を上書きしない。
- 初回は取得中、サーバー確認後は準備完了、通信切断／失敗は更新未確認として区別する。再購読の最初は全置換し、旧候補を残さない。エラーを候補0件の成功に置き換えない。認証／所属／復旧の境界ではlistener解除・世代更新・Store／個別キャッシュ／候補の消去を一体化する。
- HSの候補は有効グループ・会社・本支店の関係も確認する。Portalは現行の認可済みCallableによる範囲限定取得＋同じ共有窓口を第一案とし、Portal全件listenerのためだけにRulesを拡張しない。候補表示と保存権限の判定を分け、サーバーの保存時検証は維持する。
- 現在一覧／詳細APIは会社・本支店名をサーバー側でも取得する。Storeを足すだけではそのReadは減らない。新しいクライアント向けの応答で名称取得を省ける経路と、画面／CSV出力の共通名称解決が必要。旧クライアント互換、CSV出力時の取得失敗、無効名称の扱いを検証する。

現物のVuetify標準filterは大小文字を揃えた部分一致で、全半角やひらがな／カタカナの同一視はしない。独自N-Gram／正規化は追加しない。最終受入は21件目以降の候補、工務店変更、無効化／再有効化、同時取得、TTL期限、logout／scope／復旧世代、購読失敗・再接続、Portal越境、CSV名称取得失敗を含める。
