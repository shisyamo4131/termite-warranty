# HSC-042: 月別一覧の過去未処理分と処理済みの抽出範囲

- Status: HS確認待ち。変更案は未採用・未実装。
- Decision owner: House Solution
- 登録日: 2026-10-12
- 根拠: 本Codex会話でオーナーが「指定された年月より前の未処理分も含める仕様が邪魔をしているね。これ、要仕様確認事項として記録しておいて。業務フローとしてHSの判断が必要だ」と指示。

## 確認できている現状

対象は保険会社報告一覧、請求用一覧、保証書CSVの3画面。保険は保険期間ごと、請求・保証書は保証期間ごとの状態を扱う。

| 画面 | 現在の抽出範囲 |
| --- | --- |
| 保険会社報告一覧 | 指定年月の未報告候補と、現在の期間・満了条件に該当する過去の未処理分。報告不要は除外。記録不足は要確認として扱い、報告済み期間の再出力機能はない |
| 請求用一覧 | 保証グループと対象年月を指定し、当月以前の未請求期間を抽出。初回は申込月、延長は保証開始月が基準。請求済みは抽出しない |
| 保証書CSV | 指定月の未発行・発行済み期間と、指定月より前の未発行期間。初回は引渡月、延長は保証開始月が基準 |

現在の根拠は[仕様書](../../specification.md#2026-10-09-請求保証書のグループ別処理と取消)、[保険報告要件](../insurance-reporting.md)、[月別取得設計](../../design/monthly-queries.md)、[保証書設計](../../design/warranty-certificates.md)。関連する従来事項は[HSC-010](HSC-010-payer-contracting-party.md)、[HSC-036](HSC-036-insurance-reporting-cycle.md)、[HSC-037](HSC-037-warranty-groups.md)。本事項は現行仕様の記載誤りではなく、3業務をまたぐ抽出範囲の再確認である。

## HSへ確認する事項

1. 指定した月の作業を行う際、過去の未報告・未請求・未発行も自動で混ぜて処理する運用でよいか。指定月だけに絞る、過去未処理を別途選べるようにする、現行の自動追加を維持する、のどの扱いが業務に合うか。3業務で扱いが異なる場合も確認する。
2. 「済みも含める」を設ける場合、指定月と過去月それぞれの未処理・処理済みをどこまで抽出するか。月別の作業と処理済みの確認・再出力を、同じ一覧でどのように使い分けたいか。
3. 過去分を後の月に処理した場合、再出力では元の対象月を指定して探すのか、後の月の作業一式として探したいのか。例えば9月分を10月に処理した後、どの年月を指定して何を出したいかを確認する。

過去未処理分の扱いは処理漏れの防止と月別作業の分かりやすさに影響し、「済みも含める」の追加だけでは決められないため、HSの業務フローを踏まえて判断する。

## 検討した案と採用済みの前提を分ける

- 未採用案: 通常は指定月と過去月の未処理だけ、チェック時は指定月の処理済みも追加し、過去月の処理済みは追加しない。主担当が提案したが、オーナーは採用せずHSへの要確認事項として記録するよう指示した。
- 未採用案: 3一覧に「報告済みを含める」「請求済みを含める」「発行済みを含める」を設ける。今回の確認結果に従って採否・範囲を決める。
- オーナー確認済みの前提: 住所・物件名等が変わっている場合、CSV再出力は最新情報でよい。提出当時のCSVを完全再現することは今回求めていない。この了承を、過去分の抽出範囲や処理月単位の履歴機能への承認に広げない。

## 判断後の対応と完了条件

HSが3画面ごとの対象年月・過去未処理分・処理済み再出力の範囲を回答し、例に照らして確認する。その回答が承認された後に、仕様書、保険報告要件、検索・一覧要件、月別取得設計、保証書設計、利用者説明へ必要な変更を反映し、実装・検証の範囲を決める。取得方法や保存項目の変更が必要なら、その設計・互換性も確認する。

判断まで現行の抽出条件を維持する。過去未処理分の除外、チェック項目の追加、保存・データ変更、Dev配備は今回行わない。既に反映済みのボタン表記変更は別件として維持する。HSへの問い合わせ送信・回答受領は未実施。
