# HSC-041: ログイン通信失敗の原因と認証サービス側ログ

- Status: 未解決。ブラウザ診断はDev配備・実受信済み。元の通信失敗の原因は未特定。
- Decision owner: Project owner / Project
- 根拠: 2026-10-08、本タスクでオーナーが認証ログ・通信回復後の診断保存への対応と未解決事項整理を指示。

## 確認できた事実

Dev実画面で `auth/network-request-failed` を観測し、再読込後はログイン成功。発生時のブラウザ通信詳細は残っていない。当該時間帯のCloud認証／エラーログ検索は0件。既存Firestore計測は認証前を対象にせず、catchは画面表示のみだった。[調査証拠](../../design/evidence/prod-readiness-2026-10-08.md)。

認証アクティビティログ設定の有効化をDevに対して試行したところ、HTTP 400 / `OPERATION_NOT_ALLOWED : activity logging can only be enabled in GCIP.` で拒否された。設定変更は成立していない。Identity Platformへの変更は今回実行していない。従前の「ログ設定の有効化だけで対応できる」という説明は、この実環境の制約を確認できていなかった。

## 対応と残件

`f29f4a3f8de2787d3542801598c5758bc0795614` をDevへ配備し、実ログイン画面で再発した `auth/network-request-failed` の診断をFunctionsログで受信（2026-10-08 14:03:48 UTC）。未登録の架空アドレスで失敗経路を操作しており、アカウントは作成していない。通信不能・初回送信失敗を模擬したキューからの再送も別途実受信。診断経路の不足は解消したが、ネットワーク障害の根本原因は依然不明。

ブラウザ側の失敗を認証不要の診断専用Functionsへ送る。固定の処理区分・エラーコード・時刻・online値・ランダムな事象IDのみを扱い、資格情報・個人情報・自由文エラーを含めない。接続回復後の再送を実装し、Functions実受信を検証する。[契約](../../design/reference-store-metrics.md#認証失敗の診断経路)。

1. 元の通信失敗は原因未特定のまま残す。診断経路完成を障害原因の解決と扱わない。
2. 2026-10-08追加指示により、認証サービスは変更せず、実装済み診断で観測を続けることに決定。Identity Platformへの切替判断待ちは解消。通信失敗の原因調査は継続する。
3. 再発時に事象時刻・処理・コード・接続状態を照合する。接続前のDNS/TLS等の詳細はブラウザのエラーコードだけでは特定できない。

新規HS管理者テストアカウントの作成は承認レビューに拒否され未実行。診断経路はアカウントを作らずに検証するため、同アカウントの承認待ちを本改修全体の阻害事項にはしない。

## 完了条件

観測経路の実受信・秘密情報除外・再送と上限の試験を完了し、サービス側ログの扱いを決める。通信失敗の原因と対処は再現証拠に基づいて別途確定する。推測だけで解決済みへ移さない。
