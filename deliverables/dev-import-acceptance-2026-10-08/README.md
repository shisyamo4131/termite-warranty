# Dev一括取込み・物件名統合の受入手順

対象はDevだけ。CSVはすべて架空データです。HS提供の実データは回答があるまで取り込みません。基本試験では共通3件＋UH2件を本登録します。301件の拒否試験は登録されません。300件試験は任意の追加検証として分離しています。

## 1. テンプレートを入手する

1. [Dev](https://termite-warranty-dev.web.app)を再読込し、HS管理者でログイン。
2. 「物件・保証」→「一括取込み」を開く。
3. 「共通テンプレートをダウンロード」を押す。「物件保証一括取込テンプレート.csv」がダウンロードされる。
4. 見出し17列に「物件名」が1列あり、「施主名」がないことを確認。UHも同じテンプレート。「外部キー」列へお施主様契約Noを入れる。ファイル形式はUTF-8のCSV。

今回は下記の用意済みCSVをそのまま使えます。Excelで開いて再保存する必要はありません。

## 2. 検証用の所属を用意する

既存の実業務用の工務店や支店と混ぜないよう、以下の検証用データを画面から登録してください。同名がすでにあれば再利用します。

| 対象 | 設定 |
| --- | --- |
| 共通試験の保証グループ | 名称「DEV一括取込検証20261008」、接頭辞「DEVQA1008」、年度開始月1、外部キー必須ON、名称「検証外部キー」、有効ON |
| 共通試験の工務店 | 名称「検証用工務店20261008」、上記グループへ所属、有効ON。住所は「東京都」「千代田区」「検証用架空住所1-1」など架空の値 |
| 共通試験の支店 | 名称「検証用支店QA01」、上記工務店へ所属、支店コード「QA01」、有効ON |
| UH試験の工務店 | 名称「UH検証用工務店20261008」、既存の「UH」へ所属、有効ON。住所は架空の値 |
| UH試験の支店 | 名称「UH検証用支店9998」、上記UH工務店へ所属、支店コード「9998」、有効ON |

支店コード「QA99」は登録しません。工務店・支店は「設定」から選択した保証グループ・工務店の配下に登録します。検証用アカウントの新設は不要です。

## 3. CSVを順番に試す

毎回「一括取込み」で保証グループと工務店を選び、CSVを指定して「内容を検証」を押します。正常なCSVだけ、表示内容を確認してチェックを付け、「全件を本登録」を押してください。

| 順番／ファイル | 選択する所属 | 期待結果 |
| --- | --- | --- |
| 01-common-success-3.csv | 共通の検証グループ／工務店 | 3件本登録。物件名のみ表示。2件目は住所・資材名「不明」。引用符・カンマを含む3件目の物件名も崩れない |
| 02-existing-key-reject-2.csv | 共通 | 01の既登録キーを含むため全件棄却。新規キーの行も登録されない |
| 03-infile-duplicate-reject-2.csv | 共通 | CSV内の外部キー重複として全件棄却。対象行と理由が表示される |
| 04-unknown-branch-reject-2.csv | 共通 | 未登録支店QA99のため全件棄却。QA01の行も登録されない |
| 05-uh-success-2.csv | UH／UH検証用工務店 | 2件本登録。申込日2026-09-01、引渡日2026-10-01、最長10年。2件目は契約No先頭9997でも支店コード9998で正しく所属。住所・資材名は「不明」 |
| 06-over-limit-reject-301.csv | 共通 | 上限300件の超過で全件棄却。登録0件 |
| 07-optional-boundary-success-300.csv | 共通 | **任意の追加試験**。300件の表示・本登録が可能。実行すると架空物件300件と検証グループの保証番号が作成される。基本受入では実行不要 |

01をもう一度選んだ場合も、既登録キーの理由で全件棄却されることを確認してください。検索は保証番号完全一致です。成功時の保証番号を控え、「物件・保証」でその番号を検索して詳細確認します。基本試験で新規作成される物件は合計5件です。

拒否後に入力を変更する場合は「入力を見直す」を使います。通信結果が不明な場合は「登録結果を確認」または「同じ取込みを再送」を使い、新しい取込みとして送り直さないでください。

## 4. 名称統合も確認する

1. 既存物件を開き、一覧・詳細・編集・本登録確認で名称欄が「物件名」一つになったことを確認。
2. 架空の新規取込み物件の物件名を変更して保存し、再読込して変更が残ることを確認。外部キー・保証番号・所属は変えない。
3. 過去履歴に施主名が記録されていたものは「旧履歴の施主名（参考）」として残る。現在の入力項目とは別の旧履歴。
4. 施主電話番号は引き続き独立項目。

## 5. 報告してほしい内容と検証の範囲

01〜06の結果、テンプレートのダウンロード可否、名称統合の確認結果をこのチャットへお知らせください。不一致があればファイル名・行・画面の理由だけで調査できます。実データの転載は不要です。

検証用物件は自動削除しません。取消をしても外部キーは再利用できません。再試験用キーの変更や検証データの後片付けは、対象を特定して別途対応します。実業務の保証番号や欠番はCSVに含めていません。

CSV7本は作成後に同梱Spreadsheetライブラリで文字列の往復一致と列数を確認し、現行取込み処理で正常件数・エラーをLocal検証済み（verification.json）。02／04はサーバーの既登録キー・所属照合をDevで確認する試験であり、LocalのCSV入力検証だけでは拒否されません。**ユーザーのDev受入と300件のDev実行は未実施**です。
